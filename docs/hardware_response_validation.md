# fi-65F ハードウェア応答検証

この文書は、Fujitsu/Ricoh fi-65Fをscanner cameraとして使用するために実施した、LED・導光板・CIS周辺の実機応答検証を記録するものです。

ソフトウェアの使用方法は[`../README.md`](../README.md)、LED制御回路の設計案は[`hardware_led_control_design.md`](hardware_led_control_design.md)を参照してください。

## 1. 目的

scanner camera化では、外部レンズで結像した像だけをCISへ入力したいため、通常スキャン用の内蔵RGB LED照明を本スキャン中に停止させる必要があります。

一方でfi-65Fは、LEDを単純に外した状態では正常に初期化できません。したがって本検証では、次を切り分けました。

- 外部レンズ像をCISで取得できるか
- LEDをソフトウェアから消灯できるか
- LED/導光板を物理的に取り外せるか
- LEDを電気的に接続したまま光学的に切り離せるか
- LEDの共通線と15-pin信号の対応
- 初期化後だけLEDを遮断できる可能性

## 2. scanner cameraとしての前提確認

暗箱内にfi-65Fを置き、外部レンズで原稿面付近へ像を結像させてスキャンした結果、外部光学系による像が画像として取得できることを確認しました。

蛍光灯を被写体にした試験では像を認識できました。一方、ラインスキャンと照明フリッカーの組み合わせと考えられる縞も確認しています。

したがって、scanner camera化の主なハードウェア課題はCIS自体の交換ではなく、**内蔵RGB LEDを本スキャン中の撮像面へ入れないこと**です。

## 3. LED・導光板・CISの構造

分解したCISヘッドでは、長尺の白色導光板とLED出射部が端面でほぼ密着しています。

観察した構造上、LEDと導光板の間に機械式シャッターを追加できるクリアランスは1 mm未満です。このため、既存光学系を保持したまま可動遮光板を挿入する方法は、工作性・信頼性の両面で現実的ではないと判断しました。

LED側基板には次の4端子表記があります。

```text
C
B
R
G
```

TWAIN `ICAP_LIGHTSOURCE`でRED/BLUEを指定した際に実際の発光色が変化したため、少なくともR/Bを含む光源制御が実LEDまで到達していることは確認済みです。

## 4. ソフトウェアからのLED制御結果

WIA/TWAINの結果はREADMEにも記載していますが、ハードウェア判断に必要な要点は次です。

| 制御 | 結果 |
|---|---|
| WIAからランプOFF | 直接制御Propertyを確認できず |
| TWAIN `ICAP_LAMPSTATE` | 非対応 |
| TWAIN `ICAP_LIGHTSOURCE` | SET/read-back可能 |
| RED/BLUE切替 | 実LED色が変化 |
| `ICAP_LIGHTSOURCE=3` | readback=3でもLEDは消灯しない |

したがって、標準WIA/TWAIN CapabilityだけではLED無発光状態での本スキャンは実現できていません。

## 5. 光源ユニットを外した場合の応答

LED/導光ユニットを外してスキャンしたところ、PaperStream IPから次の異常が報告されました。

```text
フラットベッドの光量異常
Code: DS42039
Sense Key=0x4
ASC=0x680
DDES=0x7E
```

この時点で、LED/導光ユニットを恒久的に取り外してscanner camera化する方法は成立しないことが分かりました。

## 6. LEDを接続したまま光学的に切り離した場合

次に、LED/光源ユニットを**電気的には元どおり接続**したまま、本来の位置から外し、CISへ光が入らない状態でスキャンしました。

結果は同じ「フラットベッドの光量異常」でした。

この結果から、少なくとも次は実機で確認済みです。

- LED負荷が電気的に存在するだけでは正常初期化できない
- CIS側が実際に一定量の光を受けることが必要
- 光量異常は単なるLED断線検出だけでは説明できない

したがって、**LEDは初期化時に光学系へ実際に発光させる必要があり、スキャン開始前から恒久的に取り外すことはできません**。

## 7. 初期化時の強い発光

正常構成では、動作開始時にRGB LEDがフラッシュのような強い発光を行うことを確認しました。

この発光と、LEDを光学的に切り離した際の「光量異常」を合わせると、白基準または光量校正に相当する初期化処理を行っている可能性が高いと考えています。

ただし、**この強い発光が白基準校正そのものであることは推定であり、fi-65Fの内部仕様として確認したものではありません**。

設計上は、少なくとも次のシーケンスを成立させる必要があります。

```text
LED ON
  ↓
初期化時の強い発光
  ↓
CISが必要な光量を受光
  ↓
初期化成立
  ↓
LED OFF
  ↓
外部レンズ像だけで本スキャン
```

## 8. 15-pin信号とLED共通線

電源OFFで導通を追った結果、LED基板の`C`端子が、CIS基板側15-pinコネクタの**pin 2**へ接続されていることを確認しました。

```text
15-pin pin 2
     │
     └── LED board C
```

ただし現時点では、次は未確定です。

- `C`がcommon anodeかcommon cathodeか
- pin 2がLED専用電源線か、共通returnか、その他の制御線か
- pin 2の待機時/初期化時/スキャン時電圧
- pin 2を初期化後に開放しても本スキャンを継続できるか

したがって、電気設計ではpin 2をLED遮断候補として扱いますが、極性と電圧を測定してからMOSFET方式を確定します。

## 9. pin 2ジャンパー試行と現個体の状態

main board側の細ピッチコネクタ近傍からpin 2ネットを引き出すジャンパーを追加しようとしましたが、作業中にコネクタ近傍のランドを損傷しました。

組み戻した後は、本来待機中は消灯するLEDが赤色で連続点灯する状態になっています。

現時点では次のいずれかを疑っていますが、故障点は確定していません。

- pin 2への接続位置の問題
- ランド/配線剥離
- 隣接ネットとの短絡
- LED駆動回路への二次的影響

このため、**現在の個体は改造前の正常baselineではありません**。以後のLED挙動をfi-65F本来の仕様判断には使用しません。

## 10. 確認済み事項 / 推定 / 未検証

| 項目 | 状態 | 根拠 |
|---|---|---|
| 外部レンズ像をCISで取得できる | 確認済み | 暗箱 + 外部レンズの実画像取得 |
| WIAからLED消灯 | 未達 | 直接制御Propertyを確認できず |
| TWAINからLED色変更 | 確認済み | RED/BLUE指定で実発光色が変化 |
| TWAINからLED消灯 | 未達 | `ICAP_LAMPSTATE`非対応、`LIGHTSOURCE=3`でも消灯せず |
| LED/導光ユニットを外して正常スキャン | 不可 | PaperStream IPが光量異常を報告 |
| LEDを電気接続したままCISへ光を入れず正常スキャン | 不可 | 同じ光量異常を報告 |
| 初期化時に強いLED発光がある | 確認済み | 実機観察 |
| 強い発光が白基準/光量校正である | 推定 | 挙動からの推定。内部仕様未確認 |
| LED board `C` → 15-pin pin 2 | 確認済み | 電源OFFでの導通確認 |
| pin 2の極性/回路機能 | 未確定 | 電圧・電流方向未測定 |
| 初期化後にpin 2を切れば本スキャン継続可能 | 未検証 | ジャンパー作業中に基板損傷 |
| 赤LED連続点灯の原因 | 未確定 | pin 2周辺の作業影響を疑うが未解析 |

## 11. 次回再開時の条件

再開時は、正常な別個体または修復済み個体でbaselineを取り直します。

細ピッチコネクタのランドへ直接ジャンパーを付ける方法は再現性が低いため、次回は**15-pin FFC/FPC interposer / breakout**を前提とします。

次の順で進めます。

1. 正常個体で待機時のLED消灯を確認
2. pin 2と`C`の導通を再確認
3. pin 2 - GND電圧を待機/初期化/スキャン中に測定
4. pin 2の電流方向を確認
5. interposerでpin 2だけを分離
6. 手動スイッチで「初期化時ON → 強い発光後OFF」を試す
7. 本スキャンが継続できる場合のみMOSFET化

電気設計の詳細は[`hardware_led_control_design.md`](hardware_led_control_design.md)を参照してください。
